# 系统架构设计

## 分层概览

系统按整洁架构分**四环**，依赖方向一律向内：

| 环 | 目录 | 职责 | 可依赖 |
| --- | --- | --- | --- |
| 领域层 | `domain/` | 产品固有事实与不变量：表达单元、学习状态（维度三态）、评分 | QtCore |
| 应用层 | `application/` | 用例流程（改状态、同步、复习……）及所需**端口**（对外部系统的接口声明） | 领域层、QtCore |
| 适配层 | `adapter/` | 端口的实现：本地持久化、间隔重复引擎、AI 服务 | 应用层、领域层、QtCore |
| 框架层 | `framework/ui`、`framework/Main` | 界面与组装：QML、桥接对象、`main.cpp` 组合根 | 全部 |

每环由若干**组件**构成；模块（数据与接口）逐层落在 [2.2-模块设计](../2.2-模块设计/2.2-模块设计.md)——**当前只落领域层**，其余层随各自的设计启动时补入。

## 依赖规则

1. **依赖只向内**：框架 → 适配 → 应用 → 领域。反向引用（如领域引用应用、应用引用适配）不允许。
2. **领域层可依赖 QtCore，不得依赖 QtGui / QtQml / QtNetwork / QtWidgets**。QtCore 是通用库而非框架；真正要守的边界是"领域不依赖任何外层环"。
3. **层间只经接口通信**：应用层向外声明端口（抽象），适配层提供实现，框架层不绕过应用层直连适配层。
   - 例外：`main.cpp` 是**组合根**——全系统唯一"知道全部实现"的地方，负责选适配实现并注入。
4. **规则由构建系统强制**：CMake 目标依赖 `mai_domain → mai_application → mai_adapter → 可执行目标`，反向链接直接编不过——依赖方向不靠自觉。
