# 数据同步模块接口设计

## 在架构中的位置

```
AppCoordinator ──> IDataSync ──> ISRSEngine ──> AnkiConnectEngine (Anki 插件)
```

- `AppCoordinator` 通过 `IDataSync` 获取词汇记忆数据，传递给 `SceneOrchestrator` 生成学习场景。
- 学习完成后，`AppCoordinator` 通过 `IDataSync` 将复习结果回写到 Anki。
- `IDataSync` 屏蔽引擎差异，提供统一的笔记查询、复习提交和双向同步接口。
- `ISRSEngine` 是引擎适配层；`AnkiConnectEngine` 封装 AnkiConnect REST API（`localhost:8765`）。

## 核心概念

### MemEntry — 统一记忆条目

每个 `MemEntry` 对应 **一个 Anki Note + 其主 Card**。Anki 中一个 Note 可生成多张 Card（如正向+反向），我们取主 Card（`cardId`）作为复习调度单元。

| 字段 | 类型 | 说明 |
| ---- | ---- | ---- |
| `noteId` | Int64 | Anki Note ID（引擎内唯一标识） |
| `cardId` | Int64 | 主卡片 ID |
| `cardIds` | List\<Int64\> | 关联的全部卡片 ID |
| `deckName` | String | 所属牌组名称 |
| `modelName` | String | 笔记类型名称（如 "Basic"） |
| `fields` | Map\<String, String\> | 原始字段（映射到 Anki Note fields） |
| `tags` | List\<String\> | 标签 |
| `source` | EngineType | 来源引擎 |

**SRS 参数**（从 Anki Card 同步到本地缓存，用于离线显示）：

| 字段 | 类型 | 说明 |
| ---- | ---- | ---- |
| `easeFactor` | Float | 易度因子（FSRS 难度 D / SM-2 EF） |
| `intervalDays` | Float | 当前复习间隔（天） |
| `due` | Int64 | 到期时间戳 |
| `reps` | Int | 总复习次数 |
| `lapses` | Int | 遗忘次数 |
| `queue` | CardQueue | 卡片队列类型（New/Learn/Review/Due） |
| `lastReviewedAt` | Int64 | 最后复习时间戳 |

**字段映射约定**：通过 `SRSConfig.fieldMapping` 配置 app 逻辑字段到 Anki 字段名的映射。例如：

```
fieldMapping = {
  "word"   → "Front",
  "meaning" → "Back"
}
```

### Anki 核心概念对照

| Anki 概念 | App 对应 | 说明 |
| ---------- | -------- | ---- |
| Note | MemEntry | 内容载体（字段+标签） |
| Card | MemEntry.cardId | 复习单元（带 SRS 状态） |
| Deck | SRSConfig.deckName | 牌组，一组笔记的集合 |
| Note Type | SRSConfig.modelName | 字段模板（如 Basic、Cloze） |
| Ease (1-4) | EaseRating 枚举 | Again/Hard/Good/Easy |
| Queue (0-3) | CardQueue 枚举 | New/Learn/Review/Due |

### 接口方法分组

| 分组 | 方法 | 说明 |
| ---- | ---- | ---- |
| **引擎生命周期** | `connect` / `disconnect` / `isConnected` / `engineType` / `isWritable` | 连接管理、引擎状态与能力查询 |
| **牌组/模型发现** | `getDeckNames` / `getDeckInfo` / `getModelNames` / `getModelFieldNames` | 供配置选择：有哪些牌组、笔记类型、字段可用 |
| **条目查询** | `getAllEntries` / `getDueEntries` / `getEntryByNoteId` / `getEntryByCardId` / `searchEntries` | 从本地缓存查询记忆条目 |
| **笔记管理** | `addNote` / `updateNoteFields` / `deleteNote` | 笔记 CRUD，回写 Anki |
| **复习提交** | `answerCard` / `answerCards` | 提交复习结果，Anki 内部重算 SRS |
| **双向同步** | `pullFromEngine` / `pushToEngine` / `fullSync` / `lastSyncReport` | 与 Anki 的数据同步 |

### 信号

| 信号 | 触发时机 |
| ---- | -------- |
| `connected()` | AnkiConnect 连接验证成功 |
| `disconnected(reason)` | 连接断开 |
| `entriesChanged(updatedNoteIds)` | 同步完成后本地缓存有变更 |
| `syncFinished(report)` | 一次同步操作完成 |
| `errorOccurred(error)` | 引擎通信或同步过程中出错 |

## 关键设计决策

### 1. 评分体系从 SM-2 切换到 Anki Ease

当前 Anki 使用修改过的 SM-2 或 FSRS 算法，评分体系为 4 级：

| EaseRating | 值 | 含义 | Anki 行为 |
| ---------- | --- | ---- | --------- |
| `AGAIN` | 1 | 完全忘记 | 间隔重置，卡片进入 re-learn |
| `HARD` | 2 | 费力回想 | 间隔增长较少 |
| `GOOD` | 3 | 正常回想 | 间隔按正常曲线增长 |
| `EASY` | 4 | 轻松回想 | 间隔大幅增长 |

- `answerCard(cardId, ease)` 将评分转发给 AnkiConnect 的 `answerCards` API。
- **SRS 参数重算由 Anki 内部完成**，app 不重复实现 SM-2/FSRS 算法。
- 复习完成后 `pullFromEngine` 拉取卡片最新 SRS 状态更新本地缓存。

### 2. AnkiConnect 连接模型

AnkiConnect 是 Anki 桌面插件，在 `localhost:8765` 提供 HTTP JSON API：

```
POST http://localhost:8765
Content-Type: application/json

{
  "action": "cardsInfo",
  "version": 6,
  "params": { "cards": [12345, 12346] }
}

Response:
{
  "result": [...],
  "error": null
}
```

- `SRSConfig.url` 默认为 `http://localhost:8765`，可配置。
- 无需认证（本地信任）。
- `connect()` 调用 `version` API 验证 AnkiConnect 是否可用，失败则返回 false。
- 若 Anki 未运行或 AnkiConnect 未加载，连接失败。

### 3. 本地缓存优先

`getAllEntries` / `getDueEntries` / `searchEntries` 等查询方法**从本地缓存读取**：

- UI 响应不受 AnkiConnect HTTP 延迟影响（~50ms API 调用）。
- Anki 未运行 / 离线时仍可浏览已缓存的条目。
- 同步操作（`pullFromEngine`）负责更新本地缓存。
- 复习提交（`answerCards`）若 Anki 不可用，暂存本地队列，下次 `pushToEngine` 时回写。

### 4. 增量同步策略

`pullFromEngine` 使用 **mod time 增量** 而非全量拉取：

1. 记录上次同步时间 `lastSyncAt`。
2. 调用 `findNotes("deck:XXX")` 获取牌组内所有 Note ID。
3. 调用 `notesModTime` 找出 `mod > lastSyncAt` 的变更 Note。
4. 仅对变更的 Note 调用 `notesInfo` + `cardsInfo` 拉取详情。
5. 更新本地缓存，返回 `SyncReport`。

### 5. 添加笔记的字段约束

`addNote(fields, tags)` 需要先通过 `connect()` 配置 `deckName` 和 `modelName`：

1. `fields` 中的 key 必须在 `modelFieldNames` 中存在。
2. `deckName` 必须是已有牌组（Anki 不会自动创建牌组，需先调用 `getDeckNames` 确认或引导用户创建）。
3. 重复检测：Anki 根据首个字段做重复检查。`addNote` 抛出的错误将映射到 `errorOccurred` 信号。

### 6. 仅读模式兼容

- AnkiConnect 的 `isWritable() = true`，支持完整双向同步。
- 若后续接入**墨墨背单词**等无公开写 API 的引擎：`isWritable() = false`，`pushToEngine()` 返回空报告但不执行推送。`answerCards` 仅更新本地 SRS 跟踪。
- 即使引擎为只读，本地仍维护完整的 SRS 缓存，保证 AppCoordinator 逻辑无差异。

### 7. 多 Card 处理

一个 Anki Note 可能有多张 Card（如正向: Front→Back，反向: Back→Front）：

- `MemEntry.cardId` 取**首张 Card**（即正向卡）。
- `MemEntry.cardIds` 存储全部关联 Card ID。
- `getDueEntries` 按 Card 的 `due` 时间决定是否到期——只要任意一张 Card 到期即返回该条目。
- `answerCard` 指定具体 cardId，只影响该 Card 的 SRS 状态。

## ISRSEngine — 引擎适配层

```
IDataSync ──> ISRSEngine ──> AnkiConnectEngine
                     └──> MoMoBeiEngine (未来扩展)
```

| 方法 | 对应 AnkiConnect API |
| ---- | -------------------- |
| `fetchDeckNames()` | `deckNames` |
| `fetchModelNames()` | `modelNames` |
| `fetchModelFieldNames(name)` | `modelFieldNames` |
| `fetchNoteIds(query)` | `findNotes` |
| `fetchNotesInfo(ids)` | `notesInfo` |
| `fetchCardsInfo(ids)` | `cardsInfo` |
| `fetchModifiedNoteIds(since)` | `notesModTime` |
| `createNote(fields, tags)` | `addNote` |
| `updateNoteFields(id, fields)` | `updateNoteFields` |
| `deleteNotes(ids)` | `deleteNotes` |
| `submitReviews(answers)` | `answerCards` |

`AnkiConnectEngine` 实现以上接口，内部封装 HTTP 请求和 JSON 序列化。`IDataSync` 组合 `ISRSEngine` + 本地缓存（Hold），负责同步编排。

## 与周边模块的关系

| 对端模块 | 数据流向 | 内容 |
|----------|----------|------|
| AppCoordinator → IDataSync | 读 | 获取 `MemEntry` 列表，传递给 SceneOrchestrator |
| AppCoordinator → IDataSync | 写 | 学习完成后回写 `AnswerRecord`（ease 评分） |
| IDataSync → Hold | 读/写 | 本地缓存 MemEntry + 待推送的 AnswerRecord 队列 |
| IDataSync → ISRSEngine → AnkiConnect | 读/写 | HTTP REST 调用，拉取/推送数据 |
