# 数据同步模块接口设计

## 职责定位

数据同步模块（`IDataSync`）位于**应用协调模块**与**间隔重复引擎**之间，核心职责：

- **抽象 SRS 引擎差异**：统一默默背单词、Anki 等不同引擎的访问方式，对内提供一致接口。
- **记忆数据管理**：提供词汇条目的查询、更新能力，作为学习场景编排的数据源。
- **双向同步**：协调本地状态与远程引擎之间的数据一致性。
- **读写能力适配**：只读引擎（默默背单词无写入 API）与读写引擎（Anki）统一处理。

### 在架构中的位置

```
AppCoordinator ──> IDataSync ──> ISRSEngine (默默背单词 / Anki)
```

- `AppCoordinator` 通过 `IDataSync` 获取词汇记忆数据，传递给 `SceneOrchestrator` 生成学习场景。
- 学习完成后，`AppCoordinator` 通过 `IDataSync` 将结果回写到 SRS 引擎。

## 核心概念

### MemEntry — 统一记忆条目

无论底层引擎是什么，所有词汇/短语在 app 内部统一表示为 `MemEntry`：

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | String | 条目在引擎内的唯一标识 |
| `word` | String | 词汇/短语原文 |
| `meaning` | String | 释义 |
| `source` | EngineType | 来源（默默背单词 / Anki） |
| `tags` | List\<String\> | 词性/分类标签 |
| `level` | Int | 记忆等级，0 为新词 |
| `easeFactor` | Float | SM-2 易度因子 |
| `interval` | Int64 | 当前复习间隔（秒） |
| `consecutiveCorrect` | Int | 连续正确次数 |
| `totalReviews` | Int | 总复习次数 |
| `nextReviewAt` | Int64 | 下次复习时间戳 |
| `lastReviewedAt` | Int64 | 最后复习时间戳 |

### 接口方法分组

| 分组 | 方法 | 说明 |
|------|------|------|
| **引擎生命周期** | `connect` / `disconnect` / `isConnected` / `engineType` / `isWritable` | 连接、断开、查询引擎状态与能力 |
| **条目查询** | `getAllEntries` / `getDueEntries` / `getEntryById` / `searchEntries` | 从本地缓存查询记忆条目 |
| **条目更新** | `updateEntryAfterReview` / `batchUpdateEntries` / `addEntry` / `removeEntry` | 更新记忆状态，支持单条与批量 |
| **双向同步** | `pullFromEngine` / `pushToEngine` / `fullSync` / `lastSyncReport` | 与 SRS 引擎的数据同步 |

### 信号（Qt Signal）

| 信号 | 触发时机 |
|------|----------|
| `connected()` | 引擎连接成功 |
| `disconnected(reason)` | 引擎断开连接 |
| `entriesChanged(updatedIds)` | 条目数据发生变化（同步完成 / 本地更新） |
| `syncFinished(report)` | 一次同步操作完成 |
| `errorOccurred(error)` | 连接或同步过程中出错 |

## 关键设计决策

### 1. 读写能力适配

`isWritable()` 方法暴露底层引擎的写入能力：

- **默默背单词**（当前无公开 API）：`isWritable() = false`，`pushToEngine()` 返回空报告但不下推变更。
- **AnkiConnect**：`isWritable() = true`，支持完整双向同步。
- 即使引擎为只读，本地仍维护完整的 SRS 状态缓存，并提供相同的查询和更新接口，保证 AppCoordinator 逻辑无差异。

### 2. 本地缓存优先

`getAllEntries` / `getDueEntries` 等查询方法**从本地缓存读取**而非实时请求引擎，确保：

- UI 响应不受网络/引擎延迟影响。
- 离线状态下仍能正常获取数据。
- 同步操作（`pullFromEngine`）负责更新本地缓存。

### 3. 批量更新机制

`batchUpdateEntries` 支持累积多次复习结果后一次性提交，适用于：

- 多次 AI 场景练习后统一回写。
- 离线场景下本地累积，上线后批量同步。

### 4. 同步冲突处理

当前版本采用**引擎优先**策略：当本地与引擎数据冲突时，以引擎数据为准。后续版本可扩展冲突解决回调。

## 与周边模块的关系

| 对端模块 | 数据流向 | 内容 |
|----------|----------|------|
| AppCoordinator → IDataSync | 读 | 获取 `MemEntry` 列表，传递给 SceneOrchestrator |
| AppCoordinator → IDataSync | 写 | 学习完成后回写 `quality` 评分 |
| IDataSync → Persistence | 读/写 | 本地缓存 MemEntry 数据 |
| IDataSync → ISRSEngine | 读/写 | 从引擎拉取/推送记忆数据 |

## 典型流程

### 启动初始化

```
AppCoordinator       IDataSync          SRS Engine
     │                  │                   │
     ├──connect(config)─┤                   │
     │                  ├──── pull ─────────┤
     │                  │◄─── entries ──────┤
     │                  ├── 写入本地缓存 ──┤
     │◄──connected()────┤                   │
```

### 学习场景触发

```
AppCoordinator       IDataSync
     │                  │
     ├─getDueEntries()──┤
     │◄──List<MemEntry>─┤
     │                  │
     ├─ 传递给 Scene ──┤
     │  编排生成场景     │
```

### 学习结果回写

```
AppCoordinator       IDataSync          SRS Engine
     │                  │                   │
     ├─updateEntry──┐  │                   │
     │  AfterReview  │  │                   │
     │◄──────────────┤  │                   │
     │     ...       │  │                   │
     ├─fullSync()─────┤  │                   │
     │                  ├──── push ─────────┤
     │                  │◄─── result ───────┤
     │◄──syncFinished()─┤                   │
```
