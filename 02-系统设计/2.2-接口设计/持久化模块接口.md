# 持久化模块接口设计

## 职责定位

持久化模块（`Hold`）是应用的**统一存储入口**，核心职责：

- **集中存储**：所有模块的持久化数据通过 Hold 读写，统一管理备份与迁移。
- **命名空间隔离**：通过嵌套键路径区分不同模块的数据域，避免命名冲突。
- **异步写**：写操作异步落盘，不阻塞调用方。

### 在架构中的位置

```
各模块 ──> Hold
   ↑          │
   └──────────┘ (统一存储入口)
```

所有模块（AppCoordinator / DataSync / SceneOrchestrator 等）都通过 Hold 读写数据。Hold 内部对接具体存储后端（SQLite / 文件系统）。

## 接口方法

| 方法 | 说明 |
|------|------|
| `load(id, name)` | 读取数据。`id` 是命名空间路径（如 `["sessions", "session-abc"]`），`name` 是键名 |
| `save(id, name, data)` | 写入数据。按 `id` + `name` 组合定位存储位置 |
| `remove(id, name)` | 删除指定键的数据 |
| `exists(id, name)` | 检查指定键是否存在 |

### 命名空间设计

`id` 采用 **嵌套 List** 模拟目录结构：

| 示例 | 对应数据 |
|------|----------|
| `["sessions", "session-abc"]` | 会话 `session-abc` 的相关数据 |
| `["memories", "daily"]` | 每日记忆数据 |
| `["settings"]` | 应用设置 |

## 存储后端

- **SQLite** 为主要存储后端，适合结构化数据和批量查询。
- `data` 字段以 BLOB / TEXT 形式存储，序列化由调用方负责。
- 写操作使用 WAL 模式 + 异步提交，平衡性能与数据安全。

## 与周边模块的关系

| 对端模块 | 数据内容 |
|----------|----------|
| AppCoordinator | 会话列表、应用设置 |
| IDataSync | MemEntry 缓存、同步状态 |
| 其他模块 | 各自的配置与状态 |
