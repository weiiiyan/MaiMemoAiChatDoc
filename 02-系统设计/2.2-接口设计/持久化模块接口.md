# 持久化模块接口设计

## 在架构中的位置

```
各模块 ──> Hold
   ↑          │
   └──────────┘ (统一存储入口)
```

所有模块（AppCoordinator / DataSync / SceneOrchestrator 等）都通过 Hold 读写数据。Hold 内部对接具体存储后端（SQLite / 文件系统）。

## 接口总览

```plantuml
@startuml
!include 持久化模块接口.pu
@enduml
```

## 接口方法

| 方法 | 说明 |
|------|------|
| `data load(id, name)` | 读取数据。`id` 是命名空间路径（如 `["sessions", "session-abc"]`），`name` 是文件名 |
| `void save(id, name, data)` | 写入数据。按 `id` + `name` 组合定位存储位置 |
| `bool remove(id, name)` | 删除指定数据 |
| `bool exists(id, name)` | 检查指定键是否存在 |

### 使用说明

- `id` 采用 **嵌套 List** 模拟目录结构：

| 示例 | 对应数据 |
|------|----------|
| `["sessions", "session-abc"]` | 会话 `session-abc` 的相关数据 |
| `["memories", "daily"]` | 每日记忆数据 |
| `["settings"]` | 应用设置 |

- `data` 字段以 二进制数据 形式存储，序列化由调用方负责。

## 与周边模块的关系

| 对端模块 | 数据内容 |
|----------|----------|
| AppCoordinator | 会话列表、应用设置 |
| IDataSync | MemEntry 缓存、同步状态 |
| 其他模块 | 各自的配置与状态 |
