# 用例文档

> MaiMemoAiChat 的功能需求以用户视角用例描述。产品背景、业务规则与非功能约束见 [1.1-产品需求文档.md](1.1-产品需求文档.md)。

## 阅读约定

- 每个用例含：**执行者、前置条件、基本路径、后置条件、扩展路径**。
- 扩展路径用 Cockburn 编号：`1a` = 从基本路径**第 1 步**岔出的意外；字母后缀区分同一步骤的多个分支（`2a`/`2b`）；扩展自身有子步骤时用数字后缀（`2a1`）。
- **只有系统要负责处理的意外**才进扩展路径（如使用者回答错误、AI 服务/间隔重复引擎故障）；系统自身缺陷、界面跳转不算。

## 核心功能

听说读写四个场景均为核心功能。**每个短句在间隔重复引擎中对应四张卡片（听/说/读/写），由引擎独立调度；卡类型决定练习场景，没有其他活动类型。** 理解不单独存在，内嵌于练习之中（AI 在练习中提供例句/释义辅助）。

### 涉众利益（醉酒法）

唯一涉众为使用者（作者本人）。各用例须照顾的关切：

| 关切 | 绑定用例 | 对需求的约束 |
| --- | --- | --- |
| 生成的例句/场景材料与目标短句强相关、难度合适 | UC-1~UC-4 | 约束 AI 生成材料（见业务规则 5） |
| 挫败感——材料太难时能降级 | UC-1、UC-2 | 扩展路径：降低难度/补充例句 |
| 说/听真的有效——发音能被判断、音频能听懂 | UC-2、UC-3 | 质量需求：语音合成与分析准确 |
| 回写不损坏 Anki 已有记忆数据 | UC-5 | 回写失败可重试、不覆盖正确数据 |
| 练习不被强迫——可随时暂停 | UC-1~UC-5 | 扩展路径：随时暂停/结束 |

> 上游涉众：Anki 卡片数据质量（卡片缺例句/音频时体验打折，作为设计约束处理）。

### UC-1 读场景（读卡）

- **执行者**：使用者（主）；AI 服务（辅）
- **前置条件**：该短句的读卡已到期（由 UC-5 进入），或使用者主动选择该短句进行读练习。
- **基本路径**：
  1. 系统展示一个围绕目标短句的英语句子。
  2. 系统用英语提问，检查使用者是否理解。
  3. 使用者回答。
  4. 系统确认或纠正使用者的理解，展示下一个句子。
- **后置条件**：本次读练习会话已结束。
- **扩展路径**：
  - 2a 使用者表示无法理解：系统降低难度或补充例句。
  - 4a 使用者暂停或结束练习：系统结束本次练习会话。

### UC-2 听场景（听卡）

- **执行者**：使用者（主）；AI 服务（辅）
- **前置条件**：该短句的听卡已到期（由 UC-5 进入），或使用者主动选择该短句进行听练习。
- **基本路径**：
  1. 系统请求 AI 服务为目标短句生成音频并播放。
  2. 使用者听后复述或描述理解的内容。
  3. 系统验证理解是否正确，并逐步提高难度。
- **后置条件**：本次听练习会话已结束。
- **扩展路径**：
  - 1a 语音合成不可用：系统明确提示，可降级为文本展示或跳过该句。
  - 2a 使用者听不清：系统重放音频。
  - 3a 使用者理解错误：系统提示正确理解，降低难度。
  - 3b 使用者暂停或结束练习：系统结束本次练习会话。

### UC-3 说场景（说卡）

- **执行者**：使用者（主）；AI 服务（辅）
- **前置条件**：该短句的说卡已到期（由 UC-5 进入），或使用者主动选择该短句进行说练习。
- **基本路径**：
  1. 系统给出场景描述。
  2. 使用者说出对应的英语句子。
  3. 系统请求 AI 服务直接分析使用者的音频，检查表达与发音。
  4. 系统给出反馈与改进建议。
- **后置条件**：本次说练习会话已结束。
- **扩展路径**：
  - 3a 音频分析失败或无法听清：系统提示使用者重说。
  - 4a 使用者暂停或结束练习：系统结束本次练习会话。

### UC-4 写场景（写卡）

- **执行者**：使用者（主）；AI 服务（辅）
- **前置条件**：该短句的写卡已到期（由 UC-5 进入），或使用者主动选择该短句进行写练习。
- **基本路径**：
  1. 系统给出中文场景描述（中文只用于设定意思，见[业务规则](1.1-产品需求文档.md#业务规则) 4）。
  2. 使用者写出对应的英语句子。
  3. 系统检查语法与用词，给出批改与参考句。
  4. 使用者可微调句子，重复练习。
- **后置条件**：本次写练习会话已结束。
- **扩展路径**：4a 使用者暂停或结束练习：系统结束本次练习会话。

### UC-5 复习短句

- **执行者**：使用者（主）；间隔重复引擎（辅）；AI 服务（辅）
- **前置条件**：间隔重复引擎已连接；存在到期的卡片。
- **基本路径**：
  1. 系统按间隔重复引擎的调度，取出到期卡片（可能属于不同短句、不同卡类型）。
  2. 系统按卡类型进入对应场景练习（读/听/说/写，见 UC-1 至 UC-4）。
  3. 使用者对每张卡评分（忘记/困难/正常/轻松）。
  4. 系统更新间隔重复引擎中对应卡片的数据。
- **后置条件**：间隔重复引擎中到期卡片的数据已更新。
- **扩展路径**：
  - 1a 无到期卡片：提示"今日已全部完成"。
  - 4a 引擎未连接：评分暂存本地，下次连接时更新（见[非功能需求](1.1-产品需求文档.md#非功能需求与约束)）。
  - 4b 使用者暂停或结束练习：系统结束本次复习会话。

## 扩展功能

- **场景偏好设置**：使用者可设置偏好（场景主题、难度等），作为 AI 生成材料的约束。

## 补充约束

### 字段列表

- **短句**：英文句子，基础学习单元（必有明确意思）。
- **卡片**：每个短句对应四张卡（听/说/读/写），由间隔重复引擎独立调度；卡类型决定练习场景。
- **中文释义、例句**：AI 在练习中生成，辅助理解（无独立"理解"活动）。
- **评分**：忘记/困难/正常/轻松（对应 Anki Ease 1~4）。

### 业务规则

- 例句应尽可能简单、多个（学习理念）。
- 听场景难度逐步提高（UC-2 步 3）。
- 使用者可随时暂停或结束练习（UC-1~UC-5）。
- 理解内嵌于练习：AI 在练习中提供例句/释义辅助，无独立"理解"环节。
- 练习过程不记录明细；统计依赖间隔重复引擎（首版决策：Anki 已有统计，练习过程不落库）。

### 质量需求

- AI 服务需能直接分析语音音频以判断发音（UC-3 步 3）。
- 语音合成音频需清晰可懂（UC-2）。
- AI 回复流式返回，延迟可接受（见 PRD 非功能需求）。

### 设计约束

- 依赖 Anki 桌面端 + AnkiConnect（`localhost:8765`）（见 PRD 非功能需求）。

## 验收标准

- **UC-1**：能完成"看句 → AI 提问 → 回答 → 纠正/确认"的完整轮次，AI 有反馈。
- **UC-2**：能播放句子音频，使用者能描述理解内容并获得 AI 验证。
- **UC-3**：能接收使用者语音，AI 能基于音频给出表达/发音反馈。
- **UC-4**：能完成"系统给场景 → 使用者写句 → AI 批改 + 参考句"。
- **UC-5**：到期卡片能按类型进入对应场景练习并评分，Anki 中可见更新。
- **整体**：断网或 AI 故障时有明确提示，且不丢失已产生的数据；练习可随时暂停。
