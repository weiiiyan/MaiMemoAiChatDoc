# 领域实体与规则归位

> 本文把散布在 [1.1-产品需求文档.md](1.1-产品需求文档.md)、[1.2.1-复习语言符号.md](1.2-用例/1.2.1-复习语言符号.md)、[1.2.2-词库管理.md](1.2-用例/1.2.2-词库管理.md)、[1.2.3-练习偏好.md](1.2-用例/1.2.3-练习偏好.md) 中的业务规则做**性质归位**，并定义承载产品固有规则的**领域实体**及其不变量。
>
> **规则正文以各需求文档为准（单源）**——本文只做归位与定义，不改写规则、不涉及接口与实现；行文与正文冲突时以正文为准。

## 判定方法

业务规则按"与外部系统的耦合程度"分三档：

| 档位 | 含义 | 判定问题 |
| --- | --- | --- |
| **领域固有规则**（实体层） | 产品的固有事实与不变量：描述表达单元、学习状态、评分这些**产品自身对象**的存在方式与结构 | 换掉引擎 / AI / UI，这条规则还成立吗？ |
| **应用流程规则**（用例层） | 本系统为走完学习与复习流程而设的交互、生成与记账规则，随会话发生 | 没有这套软件，就不会存在这条规则 |
| **外部系统规则** | 规则本体在间隔重复引擎（存储、到期调度、统计）或 AI 服务（材料生成、语音）里；本系统不实现，只经适配层传递约束 | 规则本体在外部系统里 |

## 原则：引擎不决定太多

- **维度的集合**（读 / 听 / 说 / 写）**与维度到练习的对应关系**、**评分档位的语义**，由**产品定义**；某个表达单元实际有哪几张卡，属引擎侧的数据事实——产品不设定，也不假设齐备。
- 间隔重复引擎只负责执行：存储、到期调度、复习统计。
- 任何把产品语义**绑定到具体引擎**的措辞（如"评分对应 Anki Ease"）应理解为**适配映射**，不是领域定义——换引擎时应调整映射，而不是调整语义。
- 一句话分工：**状态归本系统，卡与调度归引擎，材料与判定归 AI。** 本系统持有的是"状态"，引擎持有的是"卡"，两者靠「同步间隔重复引擎状态」按状态对账。

## 领域实体

实体 = **关键业务数据 + 关键业务规则**的绑定模块（依据《架构整洁之道》第 20 章），不依赖引擎、AI、UI 的任何类型；只有字段、没有规则承载的数据结构是**跨边界数据契约**（随外部 schema 变化），不属实体。规则正文以归位表对应编号的来源文档为准，此处只列规则要点。

领域实体共三个：**表达单元、学习状态、评分**。需求文档中的"语言符号"、词库管理文档中的"词库条目"、复习中的表达，是同一实体的不同称呼与状态，不是不同实体。

**表达单元与学习状态是两个实体，不合并**：前者的身份是（词形，义项），来自专业词典、**换词典时整批重建**；后者的身份是（表达单元 × 维度），由使用者一次一次标记出来、**丢了不可重建**。可重建性不同，就不是同一份数据——R5"状态不随词典替换而变"正是这条差别的产物。

### 表达单元

- **关键业务数据**：词形 + 一个义项（需求文档称**语言符号**；词形可为词、短语或短句，句法长度不是边界；多义时以义项为界——同一词形的不同义项是不同表达单元）。**身份＝（词形，义项）**。条目取自**词库**——词库是项目自身的语言符号集（由专业词典转换而来），是表达单元的来源目录，分内置词库与使用者补录两层。承载它的句子是练习材料，不属实体（见 R1 与"非实体澄清"）。
- **关键业务规则**：R1（实体定义与承载句——句子**不随卡存档**、须为无歧义句）、R8（词库与判重）。
- **外部关系**：词形与义项由词库条目提供（义项可按需译为中文，AI 只翻译不编造）；处于*复习中*时，词形与义项（**不含句子**——句子由 AI 按上下文生成）在引擎侧存档。

### 学习状态

- **关键业务数据**：（表达单元 × 维度）上的一个取值——未学习 / 已掌握 / 复习中，**三态互斥**（同一时刻只一种）。**身份＝（表达单元，维度）**：同一词形的不同义项各算各的，同一义项的各维度各算各的（R8 的判重同此键）。
  - *未学习*——在词库内，既未标记为已掌握、也未标记为复习中；新词引入标出的即它（R17）；
  - *复习中*——该（表达单元，维度）在引擎里由一张卡替它执行调度（实际哪几张卡存在由引擎侧数据决定，可不足四张，R3）；
  - *已掌握*——作为 AI 生成材料用词的约束数据源（R12），该维度无卡、不受调度。**它是使用者的主观声明**（1.2.2：状态由使用者维护，系统不依据复习数据自动增减状态）——**不要与引擎的「掌握评估」混同**，后者只用来排下次复习时间，推不出这个状态。
- **关键业务规则**：R3（维度决定进入哪种练习、理解内嵌于练习）、R4（三态与六种迁移，全部由使用者显式发起，系统不自动迁移）、R5（状态属于表达单元自身：不随词典替换而变，迁移只改状态）、R6（撤卡即删除、不可逆）、R17 / R18（新词引入里的就地标记）。
- **外部关系**：*复习中* 在引擎里由**卡片**承载（只存词形与义项，**不含句子**）；*已掌握* 存于本系统。两侧本应一致，**「待同步」就是它们暂时没对上的时刻**（R26）——它不是本实体的数据，是本系统状态与引擎侧形态之间的**差异**。

### 评分

- **关键业务数据**：三档——忘记 / 困难 / 良好。
- **关键业务规则**：R7 之"档位集合固定为三档、档位表达回忆质量"——档位语义由产品定义，不随引擎变化（原则：引擎不决定太多）。
- **外部关系**：档位到引擎按钮 / 数值的对应属适配映射（引擎按钮数不要求与档位数一致，R33）。

### 词库条目

词库条目即表达单元本身（词形 + 一个义项）；词库由专业词典转换而来，分内置词库与使用者补录两层——补录条目与内置条目地位相同。表达单元的"已掌握"状态即**已掌握词库条目**（数据与规则见上节）。两者的管理操作见 [1.2.2-词库管理.md](1.2-用例/1.2.2-词库管理.md)。已掌握词库的取用方式（快照注入 system prompt）属系统设计，不在本文。

## 非实体澄清

以下对象**不是**领域实体，不要为它们做"实体化"设计：

- **引擎的卡片与记忆数据**（到期安排、复习历史、综合掌握评估）：它们是**间隔重复引擎自己的实体**——本系统不拥有、不改变，只经适配层读取并向其写入评分。读到的数据**必须翻译成领域词汇的类型再进用例**（Anki 的字段名与怪癖不外漏，例如 `due` 在 learning / review 两种状态下含义不同）；翻译后的产物是**复习用例的输入模型**，不是本系统的实体。**这条边界不因引擎改为自研而改变**——届时它是本系统内的一个独立模块，这些实体仍归它自己。
- **练习会话、练习材料、AI 建议评分、待同步标记**：因自动化而生的用例层对象。
- 需求文档字段列表中的词汇（例句、练习内的中文释义等）：辅助材料，无固有规则。
- **词库与词典**：都不是独立实体——词库是表达单元的来源目录，条目即表达单元（词形 + 义项），分内置词库与使用者补录两层；词典是词库的外部来源（专业词典，词库由它转换而来），换词典属数据替换、重建词库，不改动产品规则（状态不随词典替换而变，见 R5）。
